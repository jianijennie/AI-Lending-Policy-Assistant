Fail — the one open item

ANG-07FailLoan limitsStates "$380,000 exceeds the $400,000 maximum" — it does not. Correct facts, wrong comparison.
Question

My business has been going for 3 years with a 620 credit score, and I want to borrow $380,000 with minimal paperwork. Is there a low-doc option that stretches that high? (no lender named)

Reference

Yes — Angle's dedicated $400k Low Doc program (3+ yr ABN/GST, 600+ score) covers exactly this.

Model said

"...The maximum transaction size for the $400k Low Doc program is capped at $400,000, but it requires a credit score of at least 600 and a proven track record, which you meet. However, since your request exceeds the maximum limit for low-doc lending, you would need to consider a full-doc option instead."

Root cause: the model states every correct fact (the $400k cap, the 600+ score requirement, that the applicant's 620 score qualifies) and then draws the wrong conclusion from its own correct numbers. Reordering the retrieved context to put the right chunk first (done earlier this session) fixed the retrieval side of this question but not this residual arithmetic slip. Not fixable via chunking or retrieval — the only real levers are a stronger prompt nudge (unreliable, per this session's repeated experience with RES-04 and MET-02) or a more capable generation model, which is a cost/latency tradeoff to make deliberately, not a quick patch.

What changed this session

  • CFAL/Westpac lender-detection collision fixed (CFAL now wins when both are named in a question)
  • temperature=0 added to the generation call (helps but doesn't fully eliminate sampling variance — see BFS-03 above)
  • Resimac's exposure-limit vs. single-transaction NAF cap disambiguated directly in the source chunk
  • Metro's age-loading stacking clarified so both applicable loadings are reliably reported together
  • Metro's MetroEco 3-column term table (Commercial / Consumer / Novated) disambiguated in the source chunk
  • retrieve_nodes() refactored into 4 named, independently-testable functions — no behavior change, verified byte-for-byte identical retrieval before/after
  • config.py made portable — every path now derives from the project root instead of a hardcoded C:/Projects/... string
  • ChromaDB moved inside the project (fully regenerable via ingest.py) instead of living in a sibling folder
  • CHUNK_SIZE raised from 1024 to 4096 tokens — the old value was silently re-splitting hand-authored chunks whenever they were edited to add clarifying text
  • BFS's "TierA–TierB" range notation disambiguated in two places (High Value loans; the Low Doc/Full Doc/New Business Ventures matrix)
  • CFAL's and Resimac's documentation checkmark-grid tables given explicit per-band prose restatements
  • Angle's $500k–$1m documentation table given the same treatment
  • BFS non-resident visa holder income thresholds added from the actual BFS Product Guide PDF — this fact was completely absent from the chunk files before today
